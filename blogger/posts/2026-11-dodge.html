The first program on this site that is not BASIC. DODGE is a tiny game written in 6502 assembly, the language of the C64’s own processor: steer a ship along the bottom of the screen and dodge the rocks that fall faster and faster. It moves smoothly, 50 times a second, and the graphics chip itself tells the program when a rock hits you. All of it fits in 938 bytes.

Recorded in VICE: the rocks fall a row at a time, the ship moves every frame.

Two ways to run it

  • Download it: dodge.prg, drop it on VICE, and it starts on its own. It begins with a BASIC line, 10 SYS 2061, so RUN works too.
  • Type it in, the way magazines published machine code in the 1980s: as a BASIC program full of numbers. That is the listing below.
The title screen. The high score stays until you switch off.

The listing: a BASIC loader

Every DATA line holds twelve numbers, the bytes of the program, and a thirteenth: their sum. The loader adds up each line as it reads it, so if you mistype a number it stops and tells you which line to check, for example ?CHECKSUM ERROR IN LINE 1050. Fix that line and type RUN again. When every line is right it says OK. SYS 49152 TO PLAY and starts the game. Save it before the first RUN.

How the loader works

Lines 100–160 read the DATA twelve numbers at a time and POKE them into memory from address 49152, keeping a running total in C. The thirteenth number on each line is the total it should be. The last line, DATA -1, marks the end, and line 200 starts the machine code with SYS 49152.

Why 49152? It is $C000, a 4 KB block of RAM that BASIC never uses, so the loader and the game can be in memory at the same time. The downloadable dodge.prg is the same program assembled to run at 2061, right after its BASIC line.

Inside the machine code

The full source is below, with a comment on almost every line. Here are the ideas that make it work.

A BASIC line in front

A C64 program is loaded at 2049 ($0801), where BASIC expects its first line. So the assembler starts the file with one: 10 SYS 2061, built byte by byte. 2061 is the address right after that line, where the machine code begins. That is why RUN starts a machine-code program.

        * = $0801               ; a BASIC line: 10 SYS 2061
        .word basend, 10
        .null $9e, format("%d", start)
basend  .word 0

$9E is the token for SYS, and the address after it is written in digits, exactly as if you had typed it.

Fifty times a second

The game runs once per frame. $D012 is the raster register: the line the VIC-II is drawing right now. The program waits until it reaches line 251, just below the text area, then moves the ship and checks for a hit. Every frame takes exactly 1/50 of a second (PAL), whatever else is going on.

waitframe
-       lda raster              ; still on line 251 from last time?
        cmp #251
        beq -
-       lda raster              ; wait for line 251, below the text
        cmp #251
        bne -
        rts

The ship is a sprite

A sprite is a 24×21 picture the VIC-II draws on its own, on top of the text, anywhere on the screen. Its shape is 63 bytes, three per row; this one lives at 832 ($0340), which is block 13 of 64 bytes, so the sprite pointer at $07F8 is set to 13. Moving it means writing two numbers: Y in $D001 and X in $D000.

The screen is 320 pixels wide plus a border, so X needs nine bits. The ninth bit lives in $D010. The program keeps the position as 0–148 in PX and turns it into 24 + 2 × PX; the doubling shifts the ninth bit into the carry, and from there into $D010:

placeship
        lda #0
        sta msb
        lda px
        asl a                   ; carry = bit 8 of px * 2
        rol msb
        clc
        adc #24
        sta $d000
        lda msb
        adc #0
        sta $d010
        rts

Joystick and keys

The joystick in port 2 is read from $DC00, one bit per direction, and a bit is 0 while the stick is pushed that way: bit 2 is left, bit 3 right, bit 4 the fire button. For players without a joystick, the KERNAL keeps the key being held down in address 203 ($CB): 12 while Z is down, 23 for X, 60 for SPACE, 64 when nothing is pressed.

Falling rocks: moving the whole screen

The rocks are not sprites, just a ball character, screen code 81, the same one the BALL program POKEs. Every few frames the program copies the screen down by one row: row 23 into row 24, then row 22 into 23, and so on up to the top, bottom first so nothing is overwritten before it is copied. Then it empties the top row and drops in new rocks.

The copy uses the 6502’s indirect addressing: LDA (SRC),Y reads from the address held in zero page at SRC, plus Y. Two pointers, one row apart, and a loop of 40 columns:

scroll  lda #<(screen+23*40)    ; src: row 23
        sta src
        lda #>(screen+23*40)
        sta src+1
        ldx #23                 ; 23 rows to copy, bottom first
sc_row  lda src                 ; dst = src + 40, the row below
        clc
        adc #40
        sta dst
        lda src+1
        adc #0
        sta dst+1
        ldy #39
-       lda (src),y
        sta (dst),y
        dey
        bpl -
        lda src                 ; src one row up
        sec
        sbc #40
        sta src
        bcs +
        dec src+1
+       dex
        bne sc_row
        ldy #39                 ; empty the top row of the play area
        lda #32
-       sta screen+40,y
        dey

That is 920 bytes moved, at about 16 processor cycles each: some 15,000 cycles, comfortably inside the 19,656 of one PAL frame. In BASIC, with PEEK and POKE, the same copy takes a few seconds.

Random numbers from the sound chip

The SID’s voice 3 can play noise, and register $D41B shows its output as a number from 0 to 255. Set the noise to its highest frequency and that register becomes a free random number generator. Writing $8F to the volume register keeps voice 3 silent: the 8 in the high nibble turns its sound off while it keeps running.

Score 23, with plenty of room between the rocks. It gets tighter.

Hit or miss: the VIC-II decides

No coordinates are compared to find out whether a rock hit the ship. While the VIC-II draws the screen, it notices when a pixel of a sprite lands on a pixel of a character, and sets a bit in $D01F: bit 0 for sprite 0. The program simply reads $D01F once a frame. Reading it also clears it, which is why NEWGAME reads it once before play starts. Because the test is pixel by pixel, a rock can pass between the ship’s wings without counting.

Score 161. The rock at the ship’s right wing ended it, and 161 becomes the new high score.

Counting in decimal

SED switches the 6502 into decimal mode, where each byte holds two decimal digits (BCD): $99 + 1 gives $00 and a carry, not $9A. The score is two such bytes, 0000 to 9999, and printing it is just a matter of taking each half-byte and adding 48, the code of the digit 0. Comparing two BCD numbers works like ordinary numbers, so the high score check needs nothing special.

Getting harder

Every 32 rows the chance of a rock goes up by 16 (out of 256, three tries per row), and the delay between rows goes down by one frame, from 6 frames to a minimum of 2. That is from about 8 rows a second at the start to 25.

Help from the KERNAL

The text is printed with two routines from the C64’s ROM: PLOT at $FFF0 moves the cursor, and CHROUT at $FFD2 prints a character, colour codes included, exactly like PRINT in BASIC. All the texts sit in one table: row, column, then the characters, ending with 0.

The full source

dodge.asm, 459 lines (click to open) 
; =============================================================
; DODGE - dodge the falling rocks
; C64 Coding - c64n.blogspot.com
;
; 6502 assembly for 64tass:
;   64tass -C -a -i dodge.asm -o dodge.prg            (RUN it)
;   64tass -C -a -i -D LOADER=1 dodge.asm -o dodge-c000.prg
;                                    (the code at 49152, for the
;                                     BASIC loader: SYS 49152)
; =============================================================

        .weak                   ; -D LOADER=1 overrides this
LOADER  = 0                     ; 0: normal .prg, 1: code at $c000
        .endweak

; ---- addresses ----------------------------------------------
screen  = $0400                 ; screen memory, 40 x 25
colour  = $d800                 ; colour memory
sprptr  = $07f8                 ; sprite 0 pointer
sprite  = $0340                 ; sprite 0 shape: 832 = block 13
raster  = $d012                 ; current raster line (low 8 bits)
border  = $d020
backgr  = $d021
sid     = $d400                 ; first SID register
joy2    = $dc00                 ; joystick port 2, bits are 0 when pressed
keyheld = $cb                   ; key held down, 64 = none
keybuf  = $c6                   ; number of keys in the keyboard buffer
chrout  = $ffd2                 ; KERNAL: print a character
plot    = $fff0                 ; KERNAL: move the cursor (carry clear)

src     = $fb                   ; zero page pointers for scrolling
dst     = $fd

rock    = 81                    ; screen code of a rock: a ball
k_z     = 12                    ; keyboard matrix codes
k_x     = 23
k_space = 60
k_q     = 62

; ---- start ---------------------------------------------------
.if LOADER != 0
        * = $c000               ; typed in with the BASIC loader
.else
        * = $0801               ; a BASIC line: 10 SYS 2061
        .word basend, 10
        .null $9e, format("%d", start)
basend  .word 0
.endif

start   jsr setup
title   jsr showtitle
        jsr waitstart           ; carry set: Q was pressed
        bcs quit
        jsr newgame

; ---- the game loop: once per frame ----------------------------
loop    jsr waitframe           ; 50 times a second (PAL)
        jsr move                ; joystick or Z/X
        lda $d01f               ; sprite-background collision
        and #1                  ; did sprite 0 touch a rock?
        bne crash
        dec timer               ; time to scroll?
        bne loop
        lda delay
        sta timer
        jsr scroll              ; everything moves down one row
        jsr addrocks            ; new rocks on the top row
        jsr addscore            ; one point per row
        jmp loop

crash   jsr gameover
        jmp title

quit    lda #0
        sta $d015               ; sprite off
        sta sid+24              ; sound off
        sta keybuf              ; forget the keys pressed in the game
        lda #14
        sta border              ; the usual colours
        sta $0286               ; light blue text
        lda #6
        sta backgr
        lda #147                ; clear the screen
        jmp chrout              ; ...and its RTS goes back to BASIC

; ---- setup: once -----------------------------------------------
setup   lda #0
        sta border
        sta backgr
        sta $d017               ; sprite 0: normal size,
        sta $d01d
        sta $d01c               ; one colour,
        sta $d01b               ; in front of the text
        sta hi
        sta hi+1
        ldx #62                 ; empty the sprite block...
-       sta sprite,x
        dex
        bpl -
        ldx #shipend-ship-1     ; ...and copy the ship into it
-       lda ship,x
        sta sprite,x
        dex
        bpl -
        lda #sprite/64
        sta sprptr
        lda #7                  ; yellow ship
        sta $d027
        lda #218                ; near the bottom of the screen
        sta $d001
        ldx #24                 ; silence the SID
        lda #0
-       sta sid,x
        dex
        bpl -
        lda #$ff                ; voice 3: noise at top speed,
        sta sid+14              ; a source of random numbers
        sta sid+15
        lda #$80
        sta sid+18
        lda #$8f                ; volume 15, voice 3 not heard
        sta sid+24
        rts

; ---- title screen ----------------------------------------------
showtitle
        lda #0
        sta $d015               ; hide the ship
        lda #147
        jsr chrout
        lda #<titletxt
        ldy #>titletxt
        jsr texts
        ldx #19                 ; the high score
        ldy #19
        clc
        jsr plot
        lda hi+1
        jsr putbcd
        lda hi
        jmp putbcd

; wait for fire or space (carry clear) or Q (carry set)
waitstart
-       lda joy2                ; first wait until everything is let go
        and #$10
        beq -
        lda keyheld
        cmp #64
        bne -
-       lda keyheld
        cmp #k_q
        beq wsquit
        cmp #k_space
        beq wsgo
        lda joy2
        and #$10                ; fire button
        bne -
wsgo    clc
        rts
wsquit  sec
        rts

; ---- new game ----------------------------------------------------
newgame lda #147
        jsr chrout
        ldx #0                  ; colour memory: light grey rocks
        lda #15
-       sta colour,x
        sta colour+$100,x
        sta colour+$200,x
        sta colour+$2e8,x
        inx
        bne -
        lda #<gametxt
        ldy #>gametxt
        jsr texts
        ldx #0                  ; high score on the top line
        ldy #33
        clc
        jsr plot
        lda hi+1
        jsr putbcd
        lda hi
        jsr putbcd
        lda #0
        sta score
        sta score+1
        sta rows
        jsr showscore
        lda #74                 ; the ship in the middle
        sta px
        jsr placeship
        lda #6                  ; 6 frames per row to start with
        sta delay
        sta timer
        lda #48                 ; chance of a rock, out of 256
        sta density
        lda #1
        sta $d015               ; ship on
        jsr waitframe
        lda $d01f               ; reading it clears old collisions
        rts

; ---- wait for the next frame ---------------------------------------
waitframe
-       lda raster              ; still on line 251 from last time?
        cmp #251
        beq -
-       lda raster              ; wait for line 251, below the text
        cmp #251
        bne -
        rts

; ---- move the ship -------------------------------------------------
move    lda joy2
        and #4                  ; joystick left
        beq left
        lda keyheld
        cmp #k_z
        beq left
        lda joy2
        and #8                  ; joystick right
        beq right
        lda keyheld
        cmp #k_x
        beq right
        rts
left    lda px
        beq placeship           ; already at the left edge
        dec px
        jmp placeship
right   lda px
        cmp #148                ; right edge
        bcs placeship
        inc px

; sprite x = 24 + 2 * px: nine bits, the ninth in $d010
placeship
        lda #0
        sta msb
        lda px
        asl a                   ; carry = bit 8 of px * 2
        rol msb
        clc
        adc #24
        sta $d000
        lda msb
        adc #0
        sta $d010
        rts

; ---- scroll rows 1-23 down to rows 2-24 ----------------------------
scroll  lda #<(screen+23*40)    ; src: row 23
        sta src
        lda #>(screen+23*40)
        sta src+1
        ldx #23                 ; 23 rows to copy, bottom first
sc_row  lda src                 ; dst = src + 40, the row below
        clc
        adc #40
        sta dst
        lda src+1
        adc #0
        sta dst+1
        ldy #39
-       lda (src),y
        sta (dst),y
        dey
        bpl -
        lda src                 ; src one row up
        sec
        sbc #40
        sta src
        bcs +
        dec src+1
+       dex
        bne sc_row
        ldy #39                 ; empty the top row of the play area
        lda #32
-       sta screen+40,y
        dey
        bpl -
        rts

; ---- new rocks: three tries per row --------------------------------
addrocks
        ldx #3
-       lda sid+27              ; a random number from voice 3
        cmp density
        bcs +                   ; no rock this time
        lda sid+27
        and #63                 ; a column 0-63...
        cmp #40                 ; ...and only 0-39 count
        bcs +
        tay
        lda #rock
        sta screen+40,y
+       dex
        bne -
        rts

; ---- score: one point per row, faster every 32 rows ----------------
addscore
        sed                     ; decimal mode: 0099 + 1 = 0100
        clc
        lda score
        adc #1
        sta score
        lda score+1
        adc #0
        sta score+1
        cld
        jsr showscore
        inc rows
        lda rows
        and #31
        bne asdone
        lda density             ; more rocks...
        cmp #160
        bcs +
        adc #16
        sta density
+       lda delay               ; ...and faster, down to 2 frames a row
        cmp #2
        beq asdone
        dec delay
asdone  rts

showscore
        ldx #0
        ldy #7
        clc
        jsr plot
        lda #5                  ; white
        jsr chrout
        lda score+1
        jsr putbcd
        lda score
        ; fall through

; print a byte of BCD as two digits
putbcd  pha
        lsr a
        lsr a
        lsr a
        lsr a
        ora #$30                ; "0" + high digit
        jsr chrout
        pla
        and #$0f
        ora #$30                ; "0" + low digit
        jmp chrout

; ---- game over ------------------------------------------------------
gameover
        lda #$0a                ; voice 1: a burst of noise
        sta sid+5               ; attack 0, decay 10
        lda #0
        sta sid+6
        lda #8
        sta sid+1
        lda #$81                ; noise, gate on
        sta sid+4
        ldx #25                 ; flash the border for half a second
-       stx border
        jsr waitframe
        dex
        bne -
        stx border              ; x = 0: black again
        lda #$80                ; gate off
        sta sid+4
        lda score+1             ; a new high score?
        cmp hi+1
        bcc gonohi
        bne gohi
        lda score
        cmp hi
        bcc gonohi
gohi    lda score
        sta hi
        lda score+1
        sta hi+1
gonohi  lda #<overtxt
        ldy #>overtxt
        jsr texts
        ldx #100                ; two seconds
-       jsr waitframe
        dex
        bne -
        rts

; ---- print a table of texts: row, column, text, 0 ... $ff ----------
texts   sta src
        sty src+1
        ldy #0
tx_next lda (src),y             ; row
        bmi tx_done             ; $ff ends the table
        tax
        iny
        lda (src),y             ; column
        iny
        sty tmp
        tay
        clc
        jsr plot
        ldy tmp
-       lda (src),y             ; the text, up to a 0
        beq +
        jsr chrout
        iny
        bne -
+       iny
        bne tx_next
tx_done rts

; ---- texts: colour code first; lower case here, capitals on screen (-a) ----
titletxt
        .byte 5, 15, 158
        .text "d o d g e", 0
        .byte 8, 8, 5
        .text "dodge the falling rocks", 0
        .byte 11, 5, 155
        .text "joystick in port 2 or z and x", 0
        .byte 14, 9, 153
        .text "fire or space to start", 0
        .byte 16, 15, 153
        .text "q to quit", 0
        .byte 19, 16, 5
        .text "hi", 0
        .byte $ff
gametxt .byte 0, 1, 5
        .text "score", 0
        .byte 0, 30, 5
        .text "hi", 0
        .byte $ff
overtxt .byte 12, 15, 150
        .text "game over", 0
        .byte $ff

; ---- the ship: 24 x 21 pixels, 3 bytes a row ------------------------
ship    .byte $00,$18,$00, $00,$3c,$00, $00,$3c,$00, $00,$7e,$00
        .byte $00,$7e,$00, $00,$ff,$00, $01,$ff,$80, $03,$ff,$c0
        .byte $07,$db,$e0, $0f,$99,$f0, $1f,$18,$f8, $3c,$00,$3c
        .byte $30,$00,$0c       ; 13 rows; the other 8 stay empty
shipend

        .virtual *
px      .byte ?                 ; ship position, 0-148
msb     .byte ?
timer   .byte ?                 ; frames until the next row
delay   .byte ?                 ; frames per row
density .byte ?                 ; chance of a rock
rows    .byte ?                 ; rows survived, for the speed-up
tmp     .byte ?
score   .word ?                 ; BCD, 0000-9999
hi      .word ?
        .endv

Assembling it yourself

The source is written for 64tass, a free cross-assembler that runs on Windows, macOS and Linux:

64tass -C -a -i dodge.asm -o dodge.prg                  (starts at 2061)
64tass -C -a -i -D LOADER=1 dodge.asm -o dodge-c000.prg  (starts at 49152)
python make_loader.py dodge-c000.prg DODGE.bas

The second line builds the version at 49152, and the small script make_loader.py turns it into the DATA lines of the loader. In the Lab, Ctrl+Shift+B now assembles .asm files as well as BASIC: put 64tass.exe in the lab’s tools folder, and errors show up in VS Code at the right line.
